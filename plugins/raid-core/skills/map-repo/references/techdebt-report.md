# The tech-debt report

`map-repo` writes technical debt and risks to `docs/audit/<date>-techdebt.md` - a
dev-facing markdown report, separate from the operative `AGENTS.md` block so the agent's
session context stays clean. This is **not** a
templated HTML deliverable. It is a findings snapshot a developer scans before working in
the repo.

## Location and naming

- Path: `docs/audit/<date>-techdebt.md`, where `<date>` is the run date (`YYYY-MM-DD`).
- Create `docs/audit/` if it does not exist.
- On a same-day re-run, overwrite the current dated report rather than creating a second
  file for the same day. A new day gets a new dated file, so history accrues by date.

## Structure

Light and fixed - a short header, then findings grouped by area. No rigid template render.

```markdown
# Tech-debt report: <repo / engagement name>

<date> - generated by map-repo. Snapshot of debt and risk; not a code review verdict.

## Summary

<2-4 sentences: the headline risks and the overall shape of the debt.>

| Severity | Count |
|----------|-------|
| high     | <n>   |
| medium   | <n>   |
| low      | <n>   |

## Findings

### <Area, e.g. Ingestion>

- **[high]** <one-line problem statement> - `path/to/file.sql:42`
  <optional: one sentence on impact or a suggested direction.>
- **[medium]** <problem> - `path/to/model.py:18`

### <Area, e.g. Modelling>

- **[low]** <problem> - `models/marts/` (repo-wide; no single line)
```

## Field rules

- **Severity** is required on every finding: `high` (correctness, data-integrity, or
  security risk), `medium` (fragility, duplication, missing tests that will bite), `low`
  (hygiene, docs, minor cleanup).
- **Anchor** is a repo-relative `file:line` wherever the finding has a specific location.
  When a finding is genuinely repo-wide (a missing convention, a cross-cutting gap), record
  it with the directory or "repo-wide" instead of dropping it.
- Keep each finding to one line of problem statement plus at most one line of
  impact/direction. This is a snapshot to act on, not a remediation plan.
- **Observations, not verdicts.** Frame findings as what's fragile or missing, the same
  posture `raid-repo-research-analyst` returns - input for prioritisation, not a judgment.

## Example

```markdown
# Tech-debt report: Acme Data Platform

2026-06-24 - generated by map-repo. Snapshot of debt and risk; not a code review verdict.

## Summary

The ingestion layer swallows errors and the customer dimension logic is duplicated across
three marts. Test coverage is thin on the gold layer. No high-severity data-integrity risk
found, but the duplicated join is a correctness hazard if the layers drift.

| Severity | Count |
|----------|-------|
| high     | 0     |
| medium   | 2     |
| low      | 1     |

## Findings

### Ingestion

- **[medium]** Bronze ingest retries silently swallow source errors - `notebooks/ingest_orders.py:88`
  A failed source pull is logged as success; downstream sees stale data with no signal.

### Modelling

- **[medium]** The customer-dim join is copy-pasted across three marts - `models/marts/` (repo-wide)
  Extract to an intermediate model; drift between copies would produce inconsistent customer counts.

### Testing

- **[low]** Gold-layer models have no `unique`/`not_null` tests - `models/marts/_marts.yml:1`
```
